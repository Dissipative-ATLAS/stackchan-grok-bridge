# 让 Grok Bot 的回复自动从 StackChan 读出来

目标是把已有的 Grok Bot 接到 StackChan 上，同时继续使用原厂 AI Agent 的模型、免费语音服务、音色和设备控制。Mac 承担中转，Cloudflare Worker 作为结果信箱。

## 先把结果送回来

StackChan 通过原厂云 MCP 调用 Mac 中转的工具，中转用 webhook 将明确转交的问题发送给 Grok Bot。Bot 完成工作后，把适合朗读的中文答复 POST 到该任务的专用回调地址。Mac 主动取回结果、保存到本地，然后确认收取。

每个任务拥有独立的编号与回调 token，续查始终指向同一个任务。中继主密钥只用于 Mac 管理信箱，不交给 Bot。这个结构可以使用 Cloudflare 提供的 `workers.dev` 地址，Mac 无需公网入站连接。

## “显示了答案”与“听到了答案”要分别验证

排查中出现过这样的现象：普通聊天有声音，Grok 答复已有完整字幕、蓝灯也亮起，却没有声音。再开一轮对话，让机器人读出刚才的结果，它又能正常朗读。

这证明答复已返回、原厂音色也能朗读该内容，但不能仅凭字幕或灯光认定音频已经播放。后续验证因此同时检查工具调用、任务结果和用户实际听到的声音，没有把现象直接归因为扬声器或网络故障。

实测有效的处理是把长等待拆成多次短工具调用，并在继续查询前，让原厂 Agent 先说一句进度，例如“我还在等格洛克的回复，再查一下”。最终答复作为同一会话的工具结果交还给 Agent，继续走原厂语音通道。

## 一次提交，多次短查询

`ask_grok_bot` 只负责建立任务；`check_grok_task` 查询该任务；`cancel_grok_wait` 停止本机的等待流程。停止等待不等于撤销 Bot 已开始的工作。

每次工具调用最多等待 4.5 秒，尚无结果时返回任务编号和续查凭据。Agent 朗读进度后，携带凭据继续查询。续查不会再次提交原问题，完成、失败或需要补充信息时则返回相应答复。

`until_result` 模式取消中转自身的总时长与查询次数上限。它依靠原厂 Agent 在当前会话中继续调用工具，因此运行时需要保持会话，以及 Mac、机器人和相关服务的网络连接。

## 长任务实机验证

验证设备使用原厂 v1.6.0 固件。实际发给 Bot 的测试请求是：

> 帮我问格洛克：运行等待两分钟的命令，再回复测试完成。

结果如下：

| 检查项 | 观察结果 |
| --- | --- |
| 新任务提交 | 1 次 |
| 自动续查 | 18 次 |
| 从提交到最终结果 | 约 173 秒 |
| 用户是否追问 | 无 |
| 最终播报 | 自动出声，保留原厂音色 |

措辞也影响工具路由。单独说“等两分钟再提醒我”，可能由原厂提醒功能处理，不能据此判断 Grok 链路成功与否。测试时明确说“帮我问格洛克”，并核对中转确实收到调用，才能验证整条链路。

## 让中转长期可靠运行

项目用 macOS LaunchAgent 管理登录后的中转进程，并通过单实例文件锁避免两个进程同时写任务状态。回调结果先持久化再确认收取，重启后可以继续读取已有任务。

离线测试覆盖回调鉴权、错误地址拒绝、任务持久化、重复请求、续查凭据、取消和单实例互斥。实际部署还需要分别验证 Cloudflare 信箱，以及机器人最终是否真的播放声音。自动化测试与实机听音共同构成验证依据。

复用这套方案时，先配置自己的 MCP 地址、Webhook 和回调信箱，再用一句简短问候确认整条链路，最后进行明确路由到 Bot 的长任务测试。所有真实配置、凭据、日志和任务内容都保留在本地。
